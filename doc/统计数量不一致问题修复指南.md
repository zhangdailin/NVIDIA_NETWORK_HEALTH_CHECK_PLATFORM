# 统计数量不一致问题修复指南

## 问题描述

在多个分析标签页中，顶部指标卡片显示的数量（如"警告 20"）与下方完整数据表筛选条显示的数量（如"警告 0"）不一致。

## 根本原因

1. **顶部指标卡片**使用后端 `summary` 返回的统计数据
2. **完整数据表筛选条**使用前端 `UnifiedAnalysisPage` 重新计算的统计数据
3. 两者的统计逻辑不一致：
   - 后端统计基于后端的严重度判断逻辑
   - 前端统计基于前端 `getSeverity` 函数的判断逻辑

## 解决方案

**移除各个分析组件中自定义的 `metricCards`，让 `UnifiedAnalysisPage` 使用统一的前端计算逻辑。**

### 修复步骤

对每个分析组件执行以下操作：

1. **删除 metricCards 定义**：
```javascript
// 删除这部分代码
const metricCards = [
  {
    key: 'total',
    label: '总端口数',
    value: summary?.total_count ?? rows.length,
    description: '全部检测端口',
    icon: Database,
  },
  // ... 其他卡片
]
```

替换为：
```javascript
// 不再使用自定义 metricCards，让 UnifiedAnalysisPage 使用前端统一计算
// 这样可以确保顶部指标卡片和下方筛选条的数量一致
```

2. **移除 metricCards 传递**：
```javascript
// 修改前
<UnifiedAnalysisPage
  ...
  metricCards={metricCards}  // 删除这一行
  getSeverity={getSeverity}
  ...
/>

// 修改后
<UnifiedAnalysisPage
  ...
  getSeverity={getSeverity}
  ...
/>
```

## 技术细节

### UnifiedAnalysisPage 的统计逻辑

```javascript
// UnifiedAnalysisPage.jsx 第93-95行
const severityCounts = useMemo(() => {
  return countBySeverity(annotatedRows, (row) => row.__severity)
}, [annotatedRows])
```

这个统计使用的是：
1. 前端 `getSeverity` 函数判断每行的严重度
2. `annotateRows` 函数为每行添加 `__severity` 字段
3. `countBySeverity` 函数统计各严重度的数量

### 为什么要统一使用前端计算

1. **一致性**：确保所有显示的统计数据使用相同的逻辑
2. **准确性**：前端 `getSeverity` 函数包含了更详细的判断逻辑
3. **可维护性**：只需要维护一套统计逻辑

2. **保留 `summary` 参数**：虽然不用于指标卡片，但可能用于其他用途
3. **测试每个修复**：确保修复后功能正常
